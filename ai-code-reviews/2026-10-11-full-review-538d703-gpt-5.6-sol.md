- [P1] Force systemctl to perform a full reboot — /home/at/code/system/reboop/src/reboot.rs:70-70
  **High severity:** Modern systemd automatically substitutes a loaded kexec kernel or a staged soft reboot for plain `systemctl reboot`. That bypasses the bootloader and initrd just validated; a soft reboot also preserves `boot_id`, so `wait_for_return` rejects the healthy machine until its 30-minute deadline. Set `SYSTEMCTL_SKIP_AUTO_KEXEC=1` and `SYSTEMCTL_SKIP_AUTO_SOFT_REBOOT=1`, or explicitly detect and reject these states.

- [P1] Prefer bootctl's effective command line — /home/at/code/system/reboop/src/boot.rs:90-90
  **High severity:** In bootctl JSON, `options` is the base entry or embedded UKI command line, while `cmdline` includes global and local UKI add-ons. Because systemd-stub appends those add-ons, a later `init=` or `ip=` can override the value checked here, allowing preflight to approve a boot that uses another init or address. Prefer `cmdline` over `options` and test an entry where both differ.

- [P1] Validate IPv4 reachability for initrd network modes — /home/at/code/system/reboop/src/boot.rs:55-57
  **High severity:** Every `ip=` form whose first field is not an IPv4 address is silently discarded, including bracketed IPv6, `ip=dhcp6`, and `ip=off`; `check_initrd_addresses` then treats the empty result as safe. On a LUKS host configured only for IPv6 or with networking disabled, bounce reboots successfully but cannot reach the initrd at the mandatory configured IPv4 address to provide the password. Parse the full kernel/systemd `ip=` grammar and reject explicit configurations that provide no plausible IPv4 path.

- [P2] Validate scrub targets before rebooting — /home/at/code/system/reboop/src/bounce.rs:502-503
  **Medium severity:** Configuration only requires scrub targets to be absolute, and this loop passes them directly to btrfs after the reboot. `btrfs scrub` accepts any path inside a btrfs filesystem, so an existing typo such as `/date` instead of a separately mounted `/data` can scrub the root filesystem and report success while never scrubbing the intended filesystem; a nonexistent typo is discovered only after disruption. Before stopping services, require each target to be an exact mounted btrfs target and deduplicate targets by filesystem UUID.

- [P2] Count kernel errors as postflight problems — /home/at/code/system/reboop/src/bounce.rs:451-456
  **Medium severity:** `kernel_errors` is printed but omitted from `postflight_problems`, so a boot with error-level kernel messages still exits 0 and ends with “all is well.” The VM sequence already demonstrates this: `tests/vm/main.rs:545-549` injects an error that a later catch prints without failing. Add nonempty kernel errors to the returned problems and cover the resulting exit status.

- [P2] Verify the hostname before catch scrubs — /home/at/code/system/reboop/src/bounce.rs:500-500
  **Medium severity:** Unlike check, bounce, and stop, catch uses the returned session for postflight and destructive scrubbing without confirming that the host calls itself the configured hostname. If an address is stale or reassigned and cloned machines share a host key, catch can report and scrub the wrong machine. Apply the same hostname/FQDN identity check immediately after obtaining the session and before postflight.

- [P2] Handle cancellation after stopping services — /home/at/code/system/reboop/src/bounce.rs:290-292
  **Medium severity:** Once the first service has stopped, SIGINT or SIGTERM during another stop, the second preflight, or the reboot request terminates reboop immediately and can leave services down indefinitely without the final “Still stopped” warning. This window can last minutes because stopping and SMART checks have long deadlines. Track which units were active and install a cancellation guard that either restores them or defers cancellation until the reboot request is accepted.

- [P2] Require sustained SSH failure before declaring shutdown — /home/at/code/system/reboop/src/bounce.rs:598-600
  **Medium severity:** A single connection timeout or `kex_exchange_identification` error is accepted as proof that the machine is down. A live sshd can emit the latter while dropping pre-authentication connections because of MaxStartups or rate limiting, and transient packet loss can produce the former; if shutdown has stalled, stop can therefore return 0 and announce “down” while the host is still running. Require consecutive unreachable results over multiple intervals and avoid treating a generic pre-banner close alone as conclusive.

- [P3] Kill smartctl after its TERM grace period — /home/at/code/system/reboop/src/smart.rs:297-297
  **Low severity:** GNU `timeout` without `--kill-after` sends SIGTERM after 20 seconds but waits forever when a killable smartctl ignores it. The outer script returns after 25 seconds without waiting for that background job, leaking a timeout/smartctl pair on every check; only genuinely uninterruptible kernel I/O needs to remain. Add a short kill-after period and normalize both timeout and SIGKILL statuses to `NoAnswer` so the safety blocker remains.
